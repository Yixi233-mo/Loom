### 设计主张（FE.2 Token / FE.3 UI 依据）

1. **底色与质感**：暖白/奶油/极浅米色底，卡片与面板为半透明磨砂玻璃；背景可有极淡暖橘/杏色光晕，禁止死黑与纯白大面积。
2. **色板**：主强调 = 低饱和蜜桃橘 / 暖杏 / 陶土；辅助 = 淡鼠尾草绿 / 柔和香槟；完成/成功/已连接 = 鼠尾草绿。整体像蒙一层奶油，不扎眼。
3. **游戏化呈现**：设备/Agent/工具模块呈「技能树」节点，点亮为暖蜜桃微光，未连接为灰色可点配置；跨端同步成功用圆润暖色「成就」小卡片反馈；DSL 保存 = 解锁新功能（暖色微光对勾）。
4. **布局**：Win/Web 为悬浮暖色毛玻璃主控板 + 环绕 Spoke 工具卡片（可拖拽/折叠）；移动端为底部抽屉 + 淡边界/轻模糊分层，不用厚重阴影。

## 一、任务目标

1. Tauri 2.0 最佳实践前端框架（features/components/hooks/stores/api/styles）
2. 三端一致响应式布局与交互
3. 有设计主张的 UI（Token 体系、组件状态完整）
4. 可维护可扩展可交付（类型严格、适配层隔离）

**技术选型（FE.1）**
- 目录域结构：`features/ components/ hooks/ stores/ api/ styles/`；保留 `contracts/ shell/ platform/` 与现有实现兼容
- 路由：轻量 hash 路由（`hooks/use-router`），**不引入 React Router**（减少依赖，满足红线）
- 状态：现有自研 Store + 新增 `ui-store`；不引入 Zustand（除非后续确有必要再议）
- 样式：CSS 变量 Token（FE.2），暂不引入 Tailwind
- 通信：`api/` 统一门面 → REST / WS EventBus / Tauri IPC
