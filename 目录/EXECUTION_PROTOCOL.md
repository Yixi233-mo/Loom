# EXECUTION_PROTOCOL.md

> **执行协议**：本文件规定 Agent 每次开工的标准流程、汇报格式、异常处理与禁止事项。所有操作以此为唯一执行准则。

---

## 一、每次开工流程

### 第 1 步：读上下文

按顺序读取以下文件，建立完整项目认知：

| 顺序   | 文件           | 目的         |
| ---- | ------------ | ---------- |
| 1    | `项目介绍.md`    | 了解项目定位     |
| 2    | `方案.md`      | 了解技术架构     |
| 3    | `plan.md`    | 了解进度（末尾追加） |
| 4    | `ROADMAP.md` | 找到当前 Task  |

### 第 2 步：确认 Task

- 明确当前 Task 的**输入 / 输出 / 边界 / 验收标准**
- 若信息不足，列出 **3 个最关键的歧义点**让用户选

### 第 3 步：先写 Spec

- 把 Task 拆成 **3–7 个原子子任务**
- 每个子任务必须有**独立验收标准**

### 第 4 步：逐个实现

- **一次只做 1 个子任务**
- 完成后自测通过再进下一个
- 遇到不确定的 API，标注 `# 需确认当前版本API`，先跳过，等用户确认

### 第 5 步：回写进度

在 `plan.md` 末尾追加以下格式的记录：

```markdown
## [日期][Task编号] [任务名]

- 状态：✅ 完成 / ⚠️ 部分 / ❌ 阻塞
- 变更文件：[列表]
- 验收结果：[勾选项]
- 遗留问题：[如有]
```

### 第 6 步：下一 Task

- **只有当前 Task 验收通过，才能进下一个**
- 如果需要跳 Task，必须先说明理由并征得用户同意

---

## 二、汇报格式

每次 Task 完成后，用以下模板汇报：

```markdown
✅ [Task编号] [任务名]

📝 工作内容：
- [要点1]
- [要点2]

📁 变更文件：
- `path/to/file` — [说明]

🔄 进度已同步：
- plan.md 已追加 [日期] 记录

⚠️ 注意事项：
- [如有]

➡️ 下一个 Task：[Task编号][任务名]
```

---

## 三、遇到问题时的处理

| 情况          | 处理方式                           |
| ----------- | ------------------------------ |
| **API 不确定** | 标注 `# 需确认当前版本API`，跳过该行，先实现其他部分 |
| **需求歧义**    | 列出 2–3 个选项，让用户选                |
| **依赖未就绪**   | 先写 Mock，等依赖就绪后替换               |
| **测试失败**    | 先修测试，不跳过                       |
| **时间过长**    | 拆分 Task，先交付最小可用版本              |

---

## 四、禁止事项

| #    | 禁止行为           | 原因        |
| ---- | -------------- | --------- |
| 1    | ❌ 一次性写完所有 Task | 会导致失控     |
| 2    | ❌ 跳过验收标准       | 会导致质量崩塌   |
| 3    | ❌ 自行修改 ROADMAP | 如需调整必须先说明 |
| 4    | ❌ 引入未列在方案中的依赖  | 破坏架构一致性   |
| 5    | ❌ 执行危险命令       | 安全红线      |

---

## 五、执行原则总结

> **读上下文 → 确认 Task → 写 Spec → 逐个实现 → 回写进度 → 下一 Task**
>
> 每一步都不可跳过，每一步都可追溯。
